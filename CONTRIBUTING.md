# Contributing to the Freelance Developer Constitution

Thank you for helping make human–AI software development more accessible, independent, and accountable.

This is intended to be a **living constitution**, not a closed manifesto. You can suggest improvements, correct mistakes, offer practical examples, translate text, or propose entirely new articles.

Read [CONSTITUTION.md](CONSTITUTION.md), [LIVING_CONSTITUTION.md](LIVING_CONSTITUTION.md), and [AGENTS.md](AGENTS.md) before contributing.

## Ways to contribute

- Open an issue describing a principle, conflict, accessibility problem, or improvement.
- Propose precise text edits with a pull request.
- Suggest examples and checks that make rights like source export, portability, free access, and informed consent verifiable.
- Offer translations and clearer language for readers with different technical backgrounds.
- Bring reasoned disagreement, including proposals for alternative editions.

## Proposing an upstream amendment

1. Check existing issues and pull requests for related discussions.
2. Open an issue for a significant proposal so maintainers and contributors can discuss its scope.
3. In a fork or branch, edit the smallest relevant Markdown files.
4. Include a pull request description using the template below.
5. Respond to review questions respectfully. Upstream maintainers make the final merge decision for this repository and should give reasons for substantial decisions.
6. For major amendments, propose a version/changelog entry; preserve earlier versions using Git history or version tags.

### Pull request description template

```markdown
## Summary
What is changing and why?

## Affected articles and documents
Which parts of the constitution change?

## Constitution impact
- Human agency:
- Affordability and meaningful free access:
- Creator ownership and portability:
- Privacy, safety, and security:
- Independent adaptation / upstream governance:

## Tradeoffs and alternatives
What might be lost or made harder? What alternatives were considered?

## Evidence and verification
What examples, references, tests, or practical experience support the proposal?
What remains unverified?

## AI assistance
Was AI used in drafting or review? If so, what role did it play?

## Licensing and third-party material
Confirm you have the right to contribute the material and identify any external text or licenses.
```

## Contributions and copyright

**Licensing decision pending:** This repository is publicly visible but does **not yet have a published license** for its written contents. Public visibility is not permission to copy or redistribute copyrighted text. Maintainers should choose and document a suitable content license (for example, CC BY 4.0) before encouraging widespread redistribution of adapted editions.

Until a license is adopted:
- Issues containing your own proposals, questions, and small suggested edits are welcome.
- Before submitting substantial copyrighted text, discuss permission and the intended contribution terms with maintainers.
- Do not paste third-party articles, paid materials, or proprietary code unless you have the rights necessary to contribute them.
- Do not assume contributing automatically transfers ownership or creates a blanket license for all future uses.

When a license is adopted, update this section with the exact grant, attribution requirements, and contribution terms. Software in projects that adopt the constitution can use a separate software license.

## Collaboration expectations

- Treat participants respectfully, including people with less formal education, less money, or limited technical experience.
- Challenge an idea or implementation, not the person's dignity.
- Prioritize clear language, accessible Markdown, and examples that readers can actually follow.
- Do not share private project data, API keys, credentials, or information about others without permission.
- Identify assumptions and distinguish ideas from verified results.
- If AI contributed material, review it yourself and disclose its meaningful role. Human contributors remain accountable for what they submit.
- Avoid spam, harassment, deception, or deliberately malicious content.

## Maintainers and independent editions

Upstream maintainers can choose what is incorporated into **this repository**, with transparent reasoning. That choice must not be confused with authority over independent projects or forks.

The goal is a culture of improvement without gatekeeping. For the intended legal freedom to fork and redistribute adaptations, an explicit permissive documentation license still needs to be selected and published.

## What happens next?

After discussion, maintainers may merge, request changes, defer, or decline a proposal with an explanation. Accepted material should be reflected in the appropriate Markdown documents, and substantive changes should receive a version note.

See the [Living Constitution](LIVING_CONSTITUTION.md) for the long-term amendment philosophy.
